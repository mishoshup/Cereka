# Plan 09-01: Headless mode for CerekaGame

## Goal
Add `--headless` flag to CerekaGame that runs scripts without SDL window, outputs to stdout, auto-advances, and reports failures with source-location diagnostics.

## Files

| # | File | Change |
|---|------|--------|
| 1 | `runner/main.cpp` | Parse `--headless` and `--entry` flags. When headless: skip InitGame, skip PollEvent/HandleEvent/Draw/Present loop, replace with auto-advancing dispatch loop. Output narrate/say with source locations. Detect FAIL and exit non-zero. |
| 2 | `include/Cereka/Cereka.hpp` | Add `bool m_headless` flag to CerekaEngine (or keep headless logic in runner only — no engine change needed) |
| 3 | `CLAUDE.md` | Document `--headless` and `--entry` flags in runner section |

## Implementation

### Approach: runner-only headless logic
The cleanest approach: keep all headless logic in `runner/main.cpp`. The engine API doesn't need changes — headless mode just:
1. Skips `InitGame()` (which creates SDL window) — instead call a new headless init that sets up engine without window
2. Replaces the render loop with a dispatch-only loop
3. Captures `say`/`narrate` text after each tick via `engine.CurrentText()`

### Headless init path
- `InitGame()` currently creates SDL window + renderer + font
- Headless needs: font loaded (for text metrics? no, headless doesn't render) → actually headless doesn't need any SDL init
- Either: add `InitHeadless()` to CerekaEngine, or make `InitGame()` accept a headless flag

Actually, examining the engine: `TickScript()` dispatches instructions including SAY/NARRATE which sets text in DialogueSystem. No SDL involvement. The only SDL-dependent init is window/renderer/font.

**Simplest approach:** Call `InitGame()` normally (it works), but:
- Use `SDL_WINDOW_HIDDEN` flag (create window but don't show it) — this way InitGame succeeds without visible window
- Skip Draw/Present entirely
- Replace input with auto-advance

Even simpler: **Don't call InitGame at all** for pure script execution. The engine TickScript just needs a ScriptInterpreter with compiled instructions. But InitGame also sets up AudioManager, SceneManager, UIManager, etc. which are needed for scene/audio instructions.

**Best approach:** Modify `InitGame()` to accept a `headless` parameter (or add `InitHeadless()`) that skips window/renderer creation but initializes everything else.

### Auto-advance
After TickScript sets state to `WaitingForInput`, immediately synthesize an advance event to continue. This is the key auto-advance mechanism.

### Output
After each TickScript call, read `engine.CurrentText()` and output with source location from the instruction's `srcLine`/`srcCol`.
