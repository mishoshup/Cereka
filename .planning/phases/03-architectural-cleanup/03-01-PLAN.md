<task type="auto">
  <name>Task 3: Runtime bounds checks + error propagation (D-05)</name>
  <files>src/cereka_script.cpp, src/cereka_save.cpp, src/compiler/cereka_instruction.hpp, src/compiler/cereka_instruction.cpp, runner/main.cpp</files>
  <action>
    Four fixes:

    **1. CALL stack bounds check (cereka_script.cpp, line 145):**
    Before `si.callStack.push_back(si.pc + 1);`, add:
    ```cpp
    if (si.callStack.size() >= 32) {
        std::cerr << "[CEREKA] Call stack overflow (max 32)\n";
        changeState(CerekaState::Finished);
        return;
    }
    ```
    Use a named constant `MAX_CALL_DEPTH = 32` to match the compiler's include depth limit.

    **2. Clamp restored PC (cereka_save.cpp, line 163):**
    Replace `scriptInterpreter.pc = data.programCounter;` with:
    ```cpp
    scriptInterpreter.pc = std::min(data.programCounter,
                                     scriptInterpreter.program.empty()
                                         ? 0
                                         : scriptInterpreter.program.size() - 1);
    ```

    **3. Absolute save path (cereka_save.cpp, line 24):**
    Change `savePath()` to take the project root as a parameter or derive it. The simplest approach: use `fs::absolute("saves/slot" ...)` to resolve relative to the current working directory (which runner/main.cpp sets to project root at startup). Or store the project root path in CerekaImpl and pass it through. Since the runner already calls `fs::current_path(projectRoot)`, `fs::absolute()` works.

    Change:
    ```cpp
    static std::string savePath(int slot)
    {
        return "saves/slot" + std::to_string(slot) + ".json";
    }
    ```
    to:
    ```cpp
    static std::string savePath(int slot)
    {
        static const fs::path saveDir = fs::absolute("saves");
        return (saveDir / ("slot" + std::to_string(slot) + ".json")).string();
    }
    ```
    Also update `fs::create_directories("saves", ec)` in SaveGame to use `saveDir.parent_path()` or similarly absolute.

    **4. Compile error propagation (cereka_instruction.hpp/.cpp):**
    Change `CompileCerekaScript` return type from `std::vector<Instruction>` to `std::expected<std::vector<Instruction>, std::string>`.

    In `CompileFile()`:
    - Return `std::expected<std::vector<Instruction>, std::string>` instead of `std::vector<Instruction>`
    - On error paths (depth exceeded, file not found, Lua errors), return `std::unexpected("error message")` instead of `return {}`
    - Propagate inner errors: `auto sub = CompileFile(...); if (!sub) return std::unexpected(sub.error());`
    - Update all callers in the recursive path to propagate errors
    - In the public `CompileCerekaScript`: call `CompileFile`, return its result directly

    **Update runner/main.cpp (line 162-167):**
    The runner currently checks `if (script.empty())`. Update to:
    ```cpp
    auto scriptResult = cereka::compiler::CompileCerekaScript(entry);
    if (!scriptResult) {
        L("[FATAL] " + scriptResult.error());
        return 1;
    }
    auto &script = *scriptResult;
    ```
