# Plan 08-01: Fix inconsistent type coercion in IF_EQ/IF_NEQ

## Goal
IF_EQ and IF_NEQ fail to resolve the RHS when it's a variable name. The dispatch compares the LHS value against the literal RHS string (which is a variable name), instead of resolving the RHS variable to its value first.

## Files

| # | File | Change |
|---|------|--------|
| 1 | `src/state/cereka_states.cpp` | In IF_EQ/IF_NEQ dispatch: after resolving LHS from `variables`, also resolve `ins.b` from `variables`/`numVariables` before comparing |
| 2 | `tests/compile/inputs/coercion.crka` | Snapshot test covering string==string, string==int var, string==literal int |
| 3 | `CLAUDE.md` | No doc change needed — this is a bug fix, not a new feature |

## Implementation

In IF_EQ/IF_NEQ:
```cpp
// Resolve RHS: if it's a known variable, use its value
std::string rhs = ins.b;
auto rit = si.variables.find(ins.b);
if (rit != si.variables.end())
    rhs = rit->second;
```
