# Plan 10-02: CodeEditor Widget + LSP Client

## Objective

Build the core editing infrastructure: a custom QPlainTextEdit widget with line numbers and gutter, an LSP client that communicates with the tree-sitter-cereka server, error squiggles via syntax highlighting, and auto-complete.

---

## Tasks

### Task 1: LSP client

**Files:** launcher/lsp_client.hpp, launcher/lsp_client.cpp
**Action:**
- `LspClient` class managing child process (QProcess) → LSP server binary
- **JSON-RPC over stdin/stdout**: send `Content-Length: ...\r\n\r\n{json}` frames
- **Frame parser** (critical detail): accumulates bytes from QProcess::readyReadStandardOutput. Scans for `Content-Length: N\r\n\r\n` header, then reads exactly N bytes for the JSON body. Accumulates partial frames across multiple readyRead signals. Dispatches complete JSON-RPC messages to response handlers.
- **Request ID tracking**: every request gets a monotonically incrementing ID. Map of `pendingRequests{id: {resolve, reject, method}}`. Completion/debounce: cancel previous pending completion request before sending new one (stale completion guard).
- **Methods** (all return via QPromise or callback):
  - `initialize()` / `initialized()` — standard LSP handshake with server capabilities negotiation
  - `didOpen(uri, text)` — notify server of opened document (version: 1, increment on changes)
  - `didChange(uri, text, version)` — incremental text sync
  - `didClose(uri)` — notify server of closed document
  - `completion(uri, line, col)` → completion list (track request ID to avoid stale results)
  - `definition(uri, line, col)` → Location | null
  - `hover(uri, line, col)` → Hover text | null
  - `references(uri, line, col)` → Location[]
  - `documentSymbol(uri)` → SymbolInformation[]
- **Notifications** (server→client, handled asynchronously):
  - `textDocument/publishDiagnostics` → emit `diagnosticsReceived(uri, diagnostics)` signal
  - `window/showMessage` → emit `messageReceived(level, message)` signal
- **Lifecycle:**
  - Start: create QProcess with binary path from LspClient::resolveBinary()
  - Initialize: send initialize → receive capabilities → send initialized notification
  - Restart on crash: exponential backoff (1s, 2s, 4s, max 30s), reset on successful initialize
  - Shutdown: send shutdown request → wait for response → send exit notification → close process
  - Graceful degradation: if binary not found or crash loop detected, emit `connectionFailed()` signal, editor shows "LSP server unavailable" status bar

### Task 2: CodeEditor widget

**Files:** launcher/code_editor.hpp, launcher/code_editor.cpp
**Action:**
- `CodeEditor` class extending QPlainTextEdit
- **Line number gutter**: custom viewport margins, paint line numbers in `paintEvent` override
- **Code folding gutter**: paint fold markers (▶/▼) in left margin, fold regions via `setExtraSelections`
- **Error squiggles**: override `paintEvent` to draw wavy underlines on diagnostic ranges (received from LspClient)
- **Bracket matching**: highlight matching `{` `}` `(` `)` when cursor is adjacent using QTextCharFormat extra selections
- **Indentation guides**: paint vertical lines at each indent level in viewport margin
- **Go-to-definition**: mousePressEvent override — Ctrl+click → send LSP `definition` → navigate to file:line
- **Completer**: QCompleter with custom model, trigger on `textChanged` with debounce
- **Hover tooltip**: QToolTip on hover with `textDocument/hover` response
- **Color scheme**: dark theme matching existing launcher (Theme::* constants)

### Task 3: Syntax highlighter

**Files:** launcher/syntax_highlighter.hpp, launcher/syntax_highlighter.cpp
**Action:**
- `CrkaHighlighter` extending QSyntaxHighlighter
- Highlight .crka keywords (say, narrate, menu, if, set, label, jump, call, bg, char, etc.)
- String literals (quoted text)
- Comments (semicolons)
- Numbers
- Labels (lines starting with `label`)
- Variables (`{var_name}` in dialogue)
- Operators (`==`, `!=`, `>`, `<`, `>=`, `<=`, `+=`, `-=`, `*=`, `/=`)
- Color scheme from Theme::* constants (gold for keywords, ice-blue for strings, etc.)

### Task 4: Editor page

**Files:** launcher/editor_page.hpp, launcher/editor_page.cpp
**Action:**
- Replace the placeholder from 10-01 with the actual EditorPage
- Contains: CodeEditor instance + LspClient + file tree side panel (QListWidget of .crka files)
- Load file on tree click → `didOpen` LSP notification
- Save file → `didChange` notification
- LSP diagnostics → error squiggles in CodeEditor + diagnostic markers in gutter
- **Cross-file navigation handler**: when LSP `definition` returns a location in a different file, EditorPage opens that file in a new tab (or focuses existing tab) and scrolls CodeEditor to target line via `QTextCursor::setPosition` + `ensureCursorVisible`
- **Drop event handling**: CodeEditor accepts drops with `setAcceptDrops(true)`, handles `dragEnterEvent`/`dropEvent` to accept file paths from asset browser drag and insert them as text at cursor position
