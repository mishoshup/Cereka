Rewrite vendor/CMakeLists.txt with three changes:

1. Add WIN32 static-link gate BEFORE `add_subdirectory(SDL)` (the very first line):
```cmake
# On Windows: build SDL3* as static libraries → CerekaGame.exe has zero DLL dependencies.
# Use FORCE so the SDL CMake options override any stale cache values from a prior configure.
# Keep Linux as shared (glibc ABI coupling makes static SDL impractical across distros).
if(WIN32)
    set(BUILD_SHARED_LIBS OFF CACHE BOOL "" FORCE)
    set(SDL_SHARED        OFF CACHE BOOL "" FORCE)
    set(SDL_STATIC        ON  CACHE BOOL "" FORCE)
endif()
```

2. REMOVE the entire existing WIN32 DLL-routing foreach block (lines 22-29). After the static gate, `SDL3-shared` and friends do not exist in a Windows build — the block would error. On Linux, a separate LIBRARY_OUTPUT_DIRECTORY block (step 3) handles routing.

3. Add a UNIX Linux .so routing block AFTER `add_subdirectory(SDL_mixer)` and BEFORE `add_subdirectory(sol2)`:
```cmake
# On Linux: route SDL shared libraries into build/runtimes/linux/ alongside CerekaGame.
# This satisfies the $ORIGIN RPATH lookup (set in runner/CMakeLists.txt) and gives the
# packager a single source directory to copy .so files from.
# Note: shared libs use LIBRARY_OUTPUT_DIRECTORY, not RUNTIME_OUTPUT_DIRECTORY (which
# applies to executables and DLLs only).
if(UNIX AND NOT APPLE)
    foreach(_t SDL3-shared SDL3_image-shared SDL3_ttf-shared SDL3_mixer-shared)
        if(TARGET ${_t})
            set_target_properties(${_t} PROPERTIES
                LIBRARY_OUTPUT_DIRECTORY "${CMAKE_BINARY_DIR}/runtimes/linux")
        endif()
    endforeach()
endif()
```

The `if(TARGET ${_t})` guard is required: on Windows (static build), the `-shared` targets do not exist and the foreach would otherwise produce a CMake error.

Keep all other content (sol2, Lua, glaze, vendor INTERFACE target) unchanged.

  <files>runner/CMakeLists.txt</files>
  <read_first>
    - runner/CMakeLists.txt (full file — see current else() branch before modifying)

  <action>
Extend the existing `else()` branch's `set_target_properties` call to add two RPATH properties:

Current state:
```cmake
else()
    set_target_properties(CerekaGame PROPERTIES
        RUNTIME_OUTPUT_DIRECTORY "${CMAKE_BINARY_DIR}/runtimes/linux")
endif()
```

Change to:
```cmake
else()
    set_target_properties(CerekaGame PROPERTIES
        RUNTIME_OUTPUT_DIRECTORY "${CMAKE_BINARY_DIR}/runtimes/linux"
        INSTALL_RPATH             "$ORIGIN"
        BUILD_WITH_INSTALL_RPATH  ON)
endif()
```

`BUILD_WITH_INSTALL_RPATH ON` tells CMake to bake the INSTALL_RPATH into the binary at build time (not only at install time). This means `build/runtimes/linux/CerekaGame` will already have `$ORIGIN` as its RPATH — no `cmake --install` step needed for the RPATH to take effect. This is the standard pattern for distributable game binaries.

Do not modify anything else in runner/CMakeLists.txt.
  </action>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Filesystem → dynamic linker | RPATH controls which directories the OS dynamic linker searches for .so files |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-01 | Elevation of Privilege | Linux RPATH $ORIGIN | mitigate | `$ORIGIN` RPATH takes precedence over `LD_LIBRARY_PATH`; an attacker cannot override library resolution by setting `LD_LIBRARY_PATH` when RPATH is set. This is a security improvement over the pre-RPATH state. No additional action needed. |
| T-01-02 | Tampering | Windows static binary | accept | Static linking eliminates the DLL hijacking attack surface for SDL (no SDL DLLs to plant in the game directory). Remaining attack surface (Windows system DLLs) is outside scope — accepted for a game engine binary. |
| T-01-03 | Tampering | CMakeCache.txt SDL_STATIC cache poisoning | accept | A developer misconfiguring their own build cache has no user-facing security impact. Documented in RESEARCH.md pitfall 3 (use separate build dirs per platform). |
</threat_model>
